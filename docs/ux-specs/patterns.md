# 공통 인터랙션 · 상태

> 여러 화면이 공유하는 인터랙션·상태 표현. 화면별 특수 동작은 각 화면 문서.

## 상태 표현

- **로딩** — 데이터 도착 전 자리를 채운다(스켈레톤/플레이스홀더). 화면 전환을 막지 않는다.
- **빈 상태** — 데이터가 없을 때 다음 행동을 안내한다(예: 입력으로 유도).
- **에러** — 무엇이 실패했고 무엇을 할지 보인다. 입력값은 보존한다.
- **성공** — 비차단 토스트로 짧게 확인하고 흐름을 끊지 않는다.

## 폼

- 저장 성공 시 입력 폼은 **즉시 비워** 다음 입력에 대비한다(입력 화면의 핵심, [`entry.md`](./entry.md)).
- 검증 실패는 해당 필드 옆에 즉시 표시하고 입력값을 유지한다(금액·필수 규칙은 [`service-specs/transactions.md`](../service-specs/transactions.md)).

## 확인 다이얼로그

- 되돌릴 수 없는 동작(영구 삭제 등)은 진행 전 한 번 확인한다.
- **사용 중 삭제**(카테고리·결제수단)는 영향 건수를 먼저 보여주고 진행 여부를 묻는다(규칙은 [`service-specs/categories.md`](../service-specs/categories.md), [`service-specs/payment-methods.md`](../service-specs/payment-methods.md)).
