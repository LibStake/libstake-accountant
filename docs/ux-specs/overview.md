# UX 개요

> 가계부 PWA를 어떻게 보이고·쓰게 만들지의 원칙. 제품 전제는 [`service-specs/overview.md`](../service-specs/overview.md).

## 폼팩터 원칙

UX의 대원칙. 폼팩터가 설계를 가른다 — 모바일=입력 도구, 데스크탑=분석 도구(전제는 [`service-specs/overview.md`](../service-specs/overview.md)).

- **모바일 — 10초 룰**: 모든 작업은 10초 안에 끝낼 수 있을 만큼 단순해야 한다. 한 화면 한 작업, 단계·선택지·필수 입력을 최소화하고, 핵심 동작은 엄지 범위·키패드/피커는 하단에 둔다. 단순함의 목적은 [`service-specs/overview.md`](../service-specs/overview.md) 왜 만드는가.
- **데스크탑 — 정보 노출 최대**: 한 화면에 정보를 최대한 펼친다. 요약·내역을 넓고 촘촘하게 비교·회고할 수 있게 한다.
- 같은 데이터, 폼팩터별 우선순위만 다르다. 화면 지도는 [`navigation.md`](./navigation.md).

## 원칙

- **읽기는 한눈에** — 월 흐름은 요점부터 위에서 보인다.
- **파괴적 동작은 확인** — 되돌릴 수 없는 동작은 한 번 막는다([`patterns.md`](./patterns.md)).
- **방해 없음** — 인터럽트 없는 화면. 알림도 인앱 비차단으로만([`recurring.md`](./recurring.md)).

## 비주얼 방향

- 톤: 군더더기 없는 중립. 금액 숫자가 시각적 주인공.
- 위계: 금액 > 분류·결제수단 > 메타. 색은 지출/수입 구분과 강조에만 절제해서.
- 밀도: 폼팩터 원칙을 따른다 — 모바일은 탭 타깃을 넉넉히, 데스크탑은 정보량 우선.
- 구체 색값·타이포·토큰은 코드가 SOT(루트 §0.9) — 여기선 방향만.
