# 제품 개요

> 가계부 PWA가 무엇을·왜·누구에게. 기능별 상세는 [`CLAUDE.md`](./CLAUDE.md) 카탈로그.

## 한 줄 요약

결제 직후 폰으로 지출/수입을 10초 안에 기록하고, 구독·공과금 같은 정기 거래는 자동 추가하거나 인앱 알림으로 확인해 누락 없이 한 달 흐름을 보는 **가계부 PWA**.

## 왜 만드는가

기존 가계부 앱의 두 마찰을 없앤다.

- **입력 마찰** — 광고·로그인·과한 분류 탓에 그때그때 적기 번거롭다. 결제 직후 한 손으로 끝나야 계속 쓴다.
- **정기 지출 누락** — 매달 빠져나가는 돈을 매번 수동 입력하면 자주 빠뜨린다. 자동/반자동으로 메워야 요약이 믿을 만하다.

운영 비용은 도메인을 빼면 월 $0를 목표로 한다.

## 누가 쓰는가

지출을 빠르게 적고 한 달 흐름을 보고 싶은 일반 사용자. 누구나 가입해 자기 가계부를 관리한다. 주로 **모바일 웹브라우저**(홈 화면 설치 PWA)로 결제 직후 즉시 입력하고, **데스크탑 브라우저**로 월말 회고한다. 각 사용자의 데이터는 서로 격리된다(사용자 단위 스코프, [`auth.md`](./auth.md)).

## 범위 밖 (Non-goals)

- 가계부 공유·협업 — 한 가계부를 여러 사람이 함께 쓰는 가족 공유·권한 분리. 각 사용자는 자기 가계부만 관리한다.
- 은행·카드 자동 연동(스크래핑/오픈뱅킹).
- OS/모바일 푸시 알림 — 웹브라우저 전제. 정기 알림은 인앱으로만([`recurring.md`](./recurring.md)).
- 실제 청구 자동 대사 — 정기 거래는 사용자가 등록한 예정값일 뿐, 실 결제와 자동으로 맞추지 않는다.
- 결제수단 잔액 관리 — 카드/계좌는 라벨일 뿐 잔액·한도·이체를 추적하지 않는다([`payment-methods.md`](./payment-methods.md)).
- 오프라인 사용 — 웹+서버 전제. PWA는 홈 화면 설치/standalone 용도이며 오프라인 캐싱은 하지 않는다.

## 플랫폼 전제

- **모바일** = 입력 도구(마찰 0), **데스크탑** = 분석 도구. 폼팩터별로 다르게 설계한다.
- 시간대는 한국 시간(KST) 고정 — 발생일시·정기 결제일시·재조정의 기준이 모두 같다.
- 통화는 원(KRW) 단일. 금액 형식 규칙은 [`transactions.md`](./transactions.md).

## 성공 지표

- 거래 1건 입력 평균 ≤ 10초.
- 정기 거래로 인한 지출 누락 0.
- 월말에 요약 화면만 봐도 한 달 지출 패턴이 보인다.

## 리스크 / 가정

| 항목 | 영향 | 대응 |
|---|---|---|
| 입력을 까먹는다 | 데이터 누락 → 요약 신뢰도 하락 | 홈 화면 단축 + 정기 거래 자동화 |
| 앱 미접속 중 자동추가 지연 | 최신성 저하(데이터는 다음 진입 시 정확) | 앱 진입 시 재조정으로 밀린 회차 반영 |
| 정기 등록값 ≠ 실제 청구액 | 요약 부정확 | 알림 승인 모드로 확인 후 사후 수정 |
| 푸시가 없어 알림을 놓침 | 정기 확인 지연 | 알림 노출 윈도 + 만료 처리 옵션([`recurring.md`](./recurring.md)) |
| PIN 무차별 / 쿠키 탈취 | 무단 접근 | 디바이스 토큰 + 실패 한도 잠금([`auth.md`](./auth.md)) |
