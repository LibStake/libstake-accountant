# 정기 거래

> 구독·공과금처럼 반복되는 지출/수입을 자동 추가하거나 인앱 알림으로 확인한다.

## 시나리오 — 등록과 처리

1. 정기 거래를 등록한다: 등록명 · 종류(지출/수입) · 카테고리(선택) · 액수 · 결제수단(선택).
2. **반복 주기**를 고르고(연 / 월 / 주 / 일) 주기에 맞춰 **결제일시**를 지정한다.
3. **처리 모드**를 택한다(둘 중 하나):
    - **자동 추가** — 도래 시각이 되면 자동으로 내역에 거래를 추가한다.
    - **알림 승인** — 도래일 기준 알림 윈도 동안 인앱 알림으로 표시한다. 승인 → 내역에 추가, 해제 → 이번 회차만 건너뜀.
4. 알림 승인 모드에서 윈도가 지나도록 응답이 없으면 등록 시 고른 **만료 처리**를 따른다.
5. 추가되는 거래의 발생일시는 그 회차의 결제일시로 기록된다.

## 도메인

- **정기 거래(Recurring transaction)** — 반복 규칙(주기 + 결제일시)과 금액·카테고리·처리 모드를 가진 *정의*. 실제 돈 이동이 아니라 "거래를 만들어내는 틀". 지출·수입 모두 가능.
- **도래 회차(Occurrence)** — 정기 거래가 특정 결제일시에 발화한 한 인스턴스. 상태(대기/승인/스킵/자동추가)와 생성된 거래로의 연결을 가진다. *같은 정기 거래의 같은 결제일시는 1개만 존재* — 재조정을 여러 번 돌려도 중복 거래가 생기지 않게 하는 핵심.

## 규칙

- **결제일시 인코딩**: 연간 = 월+일+시각, 월간 = 일+시각, 주간 = 요일+시각, 매일 = 시각.
- **말일 클램프**: 지정일이 그 달의 말일을 넘으면 말일로 보정한다(예: 매월 31일 → 2월은 28/29일).
- **모드 택1**: 한 정기 거래는 자동 추가 또는 알림 승인 중 하나. 동시 적용하지 않는다.
- **알림 윈도**: 도래일 기준 일정 구간에만 인앱 알림으로 노출한다.
- **승인 / 해제**: 승인 → 그 회차의 결제일시로 거래 생성. 해제 → 그 회차만 건너뜀(다음 회차 영향 없음).
- **만료 처리**(알림 모드, 윈도 경과 미응답) — 정기 거래별 옵션:
    - *스킵* — 적지 않는다(미확인 금액을 임의로 만들지 않음).
    - *추가* — 자동으로 거래 추가(실제 결제됐을 가능성이 높은 구독 등; 사후 수정·삭제 가능).
    - *계속 보류* — 응답할 때까지 대기 목록에 계속 표시한다.
- **멱등 재조정**: 같은 정기 거래 + 같은 결제일시 회차는 최대 1개. 재조정·자동추가를 여러 번 실행해도 중복 거래를 만들지 않는다.
- **재조정 시점**: 앱 진입 시 실행해 밀린 회차를 그때 메운다. 앱을 안 열면 다음 진입까지 반영되지 않지만, 거래는 결제일시 기준으로 채워지므로 누락이 아니라 지연이다.
- **정기 거래 삭제**: 미래 회차 생성을 멈춘다. 이미 만들어진 거래는 보존하고, 대기 중 회차는 제거한다.

## 기본값

- 알림 윈도: 도래일 기준 D-3 ~ D+5.
- '계속 보류'는 자동 정리하지 않는다 — 승인/해제할 때까지 알림에 남는다.
