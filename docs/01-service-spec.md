# 서비스 기획 — 가계부 PWA

> 이 문서는 **무엇을 / 왜** 만드는지를 정리한다.
> 어떻게(스택·아키텍처)는 `CLAUDE.md`, 어떻게 생겼는지(UI/UX)는 `docs/02-ux-spec.md`.

---

## 1. 한 줄 요약

결제 직후 폰으로 지출/수입을 10초 안에 기록하고, 구독·공과금 같은 **정기 거래**는 자동 추가하거나 인앱 알림으로 확인해 누락 없이 한 달 흐름을 보는 **1인용 가계부 PWA**.

## 2. 배경 / 동기 (Why)

기존 가계부 앱의 두 마찰을 없애는 게 목적이다.

- **입력 마찰** — 광고·로그인·과한 분류 탓에 "그때그때" 적기 번거롭다. 결제 직후 한 손으로 끝나야 계속 쓴다.
- **정기 지출 누락** — 구독·공과금처럼 매달 빠져나가는 돈을 매번 수동 입력하면 자주 빠뜨린다. 자동/반자동으로 메워야 요약이 믿을 만해진다.

운영 비용은 도메인을 빼면 월 $0를 목표로 한다(근거·구조는 `CLAUDE.md`).

## 3. 타겟 사용자 / 페르소나

- **주 사용자**: 본인 1명. **모바일 웹브라우저**(홈 화면 설치 PWA, 단 OS 푸시는 사용 안 함)로 결제 직후 즉시 입력. 데스크탑 브라우저로는 월말에 회고/분석.
- **제외 사용자**: 가족 공유, 다중 사용자, 권한 분리.

## 4. 핵심 사용 시나리오 (Use cases)

### UC1 — 결제 직후 즉시 지출 입력
1. 물품을 구매한 뒤 앱을 연다 (기본 랜딩 = 입력 화면).
2. **지출명**, **액수**, **카테고리**, (선택) **결제수단**(카드/계좌) · **메모**를 입력한다.
3. **시간은 현재 시각(KST)으로 자동 기록**되며, 필요하면 그 자리에서 수정한다.
4. 저장하면 폼이 즉시 비워진다 — "그때그때"의 핵심.
5. 이후 내역 화면에서 해당 거래를 **수정·삭제**할 수 있다.

### UC2 — 정기 거래 등록과 처리
1. 정기 거래를 등록한다: **등록명**, **종류(지출/수입)**, **카테고리**(선택), **액수**, (선택) **결제수단**.
2. **반복 주기**를 고른다: 연간 / 월간 / 주간 / 매일. 주기에 맞춰 **결제일시**를 지정한다.
    - 연간 = 월 + 일 + 시각, 월간 = 일 + 시각, 주간 = 요일 + 시각, 매일 = 시각.
3. **처리 모드**를 택한다 (둘 중 하나):
    - **자동 추가** — 도래 시각이 되면 자동으로 내역에 거래를 추가한다.
    - **알림 승인** — 도래일 기준 **D-3 ~ D+5** 동안 인앱 알림으로 표시한다. 알림에서 **승인** → 내역에 추가, **해제** → 이번 회차만 건너뜀.
4. 알림 승인 모드에서 윈도(D-3~D+5)가 지나도록 응답이 없으면, 등록 시 고른 **만료 처리**(스킵 / 추가 / 계속 보류)를 따른다.
5. 추가되는 거래의 발생일시는 **그 회차의 결제일시**로 기록된다.

### UC3 — 결제수단(카드/계좌) 관리
1. 관리 화면에서 카드/계좌를 추가한다(이름 · 종류). **잔액은 다루지 않는다** — 결제수단은 "무엇으로 냈는지" 라벨일 뿐.
2. 거래·정기 거래 등록 시 결제수단으로 선택할 수 있다.
3. 더 이상 쓰지 않는 카드/계좌는:
    - **아카이브** — 선택 목록에서 사라지고 관리 화면에만 남는다(카드 유효기간 만료 등). 기존 거래의 결제수단 표시는 유지.
    - **삭제(완전 삭제)** — 그 결제수단으로 등록된 거래가 있으면 먼저 확인하고, 진행하면 해당 거래의 결제수단만 비운다(거래 자체는 보존).

### UC4 — 로그인 / 빠른 잠금해제
1. 앱에 접속하면 인증을 거친다. 처음이거나 유효기간이 지난 브라우저면 **이메일 + 비밀번호**로 로그인한다.
2. 한 번 로그인한 브라우저는 일정 기간(유효기간) 동안 기억된다 → 다음 접속 시 **숫자 PIN 키패드**가 바로 떠서 PIN만으로 들어간다.
3. 키패드 화면엔 항상 **"일반 로그인으로"** 버튼이 있어 이메일+비밀번호로 전환할 수 있다.
4. PIN을 여러 번 틀리면 그 브라우저의 빠른 로그인이 해제되고 일반 로그인을 요구한다.

## 5. 기능 목록 (Functional requirements)

> 우선순위로 정렬. P0(MVP) / P1(다음) / P2(언젠가). 구현 순서는 `CLAUDE.md` §11.

### P0 — MVP에 반드시
- [ ] 인증: 이메일+비밀번호 로그인 + 기억된 브라우저의 빠른 PIN 잠금해제(UC4)
- [ ] 거래 입력(지출/수입): **지출명** · 액수 · 카테고리 · **발생일시(기본 now, 수정 가능)** · 메모(선택)
- [ ] 거래 목록(월 단위) + 수정·삭제
- [ ] 월간 요약(총지출/총수입, 카테고리별 합계)
- [ ] 카테고리 시드 + 추가·수정·삭제
- [ ] PWA(홈 화면 설치, standalone) — 오프라인 미지원

### P1 — MVP 이후

**결제수단 (UC3)**
- [ ] 카드/계좌 CRUD + 아카이브
- [ ] 거래·정기 거래에 결제수단 선택 부착(선택)
- [ ] 삭제 시 사용 거래 확인 → 진행하면 해당 거래의 결제수단만 비움(set null)
- [ ] 내역 결제수단 필터

**정기 거래 (UC2)**
- [ ] 정기 거래 정의 CRUD(주기 · 결제일시 · 모드 · 만료 처리 · 결제수단)
- [ ] 도래 재조정(reconcile): 앱 진입 시 밀린 회차 처리 — 자동추가분 생성 / 알림 대기 생성 / 만료 처리
- [ ] 인앱 알림: 윈도 내 대기 회차 목록 + 승인 · 해제
- [ ] 만료 처리 옵션(스킵 / 추가 / 계속 보류) — 정기 거래별
- [ ] 정기 출처 거래 표시(내역에서 배지)

**데이터 내보내기 (백업 대용)**
- [ ] 전체 데이터를 컬렉션별 JSON으로 묶어 zip 다운로드(`/api/export`) — 요약의 관리에서 버튼. 자동 백업 인프라 대신 사용자 주도 export로 갈음(기술 설계 `CLAUDE.md` §8).

### P2 — 백로그
- [ ] 서버 cron 백스톱 — 앱 미접속 중에도 자동추가가 도래 시각에 반영
- [ ] 정기 거래 일시정지 / 종료일
- [ ] 예산 한도 알림, 검색, 월 비교, CSV export, 라이트 모드

## 6. Non-goals (명시적 제외)

- 다중 사용자 / 가족 공유 / 권한 분리
- 은행·카드 자동 연동(스크래핑/오픈뱅킹)
- **OS / 모바일 푸시 알림(Web Push)** — 웹브라우저 사용 전제. 정기 거래 알림은 **인앱으로만** 표시한다.
- **실제 청구 자동 대사** — 정기 거래는 사용자가 등록한 *예정값*일 뿐, 실 결제와 자동으로 맞춰보지 않는다.
- **결제수단 잔액 관리** — 카드/계좌는 결제수단 라벨일 뿐, 잔액·한도·이체를 추적하지 않는다.
- **오프라인 사용 / 오프라인 입력** — 웹 + API 전제. 인터넷 연결이 없으면 동작하지 않는다. PWA는 홈 화면 설치/standalone 용도이며 오프라인 캐싱은 하지 않는다.
- 다중 통화 — KRW 단일 통화로 가정한다.

## 7. 도메인 개념 (Domain model)

> 데이터가 아니라 *개념*. 데이터 모델(Firestore)은 `CLAUDE.md` §4.

- **거래(Transaction)** — 한 건의 돈 이동. 지출명 · 금액(양의 정수 KRW) · 종류(expense/income) · 카테고리 · 결제수단(선택) · **발생일시(KST)** · 메모. 수동 입력 또는 정기 거래에서 생성. 라이프사이클: 생성 → (수정) → 삭제(hard delete, 복구 보장 없음 — 주기 export로 대비).
- **카테고리(Category)** — 거래에 붙는 분류 라벨. **kind와 무관**(지출/수입 양쪽에 쓸 수 있음). 사용 중이면 확인 후 삭제(거래·정기의 카테고리는 비워짐).
- **결제수단(Payment method)** — 카드 또는 계좌. "무엇으로 냈는지" 라벨이며 **잔액을 추적하지 않는다**. 거래·정기 거래에 선택적으로 붙는다. 아카이브(선택 목록에서 숨김) 또는 완전 삭제 가능.
- **정기 거래(Recurring transaction)** — 반복 규칙(주기 + 결제일시)과 금액 · 카테고리 · 처리 모드를 가진 *정의*. 실제 돈 이동이 아니라 "거래를 만들어내는 틀". **지출 · 수입 모두** 가능.
- **도래 회차(Occurrence)** — 정기 거래가 특정 결제일시에 발화한 한 인스턴스. 상태(대기 / 승인 / 스킵 / 자동추가)와 만들어진 거래로의 연결을 가진다. *같은 정기 거래의 같은 결제일시는 1개만 존재* — 재조정을 여러 번 돌려도 중복 거래가 생기지 않게 하는 핵심.
- **요약(Summary)** — 월 단위 집계. 발생일시의 연-월로 묶는다.

## 8. 비즈니스 룰 (Business rules)

> 코드에는 안 보이지만 합의된 규칙. 정기 거래 룰의 **단일 출처**(CLAUDE.md §4/§5는 여기를 참조).

- 금액은 항상 **양의 정수(KRW, 원 단위)**. 음수/소수 금지.
- `kind`(`expense | income`)는 **거래·정기 거래의 속성**이며 카테고리와 독립. 카테고리는 kind를 갖지 않는다.
- 카테고리 삭제: 사용 중이면 먼저 확인(409 + 사용 건수) → 진행하면 거래·정기의 `category_id`를 비우고(set null) 삭제. 거래는 보존(결제수단과 동일 패턴).
- 거래 삭제는 hard delete. 복구 보장 없음 — 주기 export(`CLAUDE.md` §8)로 대비.
- **시간대는 Asia/Seoul(KST) 고정.** 거래 발생일시 · 정기 결제일시 · 재조정의 'now' 모두 KST 기준.
- **정기 결제일시 인코딩**: 연간 = 월+일+시각, 월간 = 일+시각, 주간 = 요일+시각, 매일 = 시각.
- **말일 클램프**: 월간/연간에서 지정일이 해당 월의 말일을 넘으면 그 달 말일로 보정(예: 매월 31일 → 2월은 28/29일).
- **모드 택1**: 정기 거래 1건은 '자동 추가' 또는 '알림 승인' 중 하나. 동시 적용하지 않는다.
- **알림 윈도 = D-3 ~ D+5 (고정)**: 도래일 기준 이 구간에만 인앱 알림으로 노출.
- **승인 / 해제**: 승인 → 그 회차의 결제일시로 거래 생성. 해제 → 그 회차만 건너뜀(다음 회차에 영향 없음).
- **만료 처리(알림 모드, D+5 경과 미응답)** — 정기 거래별 옵션:
    - `스킵` — 적지 않음(미확인 금액을 임의로 만들지 않음).
    - `추가` — 자동으로 거래 추가(실제로 결제됐을 가능성이 높은 구독 등; 사후 수정·삭제 가능).
    - `계속 보류` — 응답할 때까지 대기 목록에 계속 표시(윈도를 넘겨 남음).
- **멱등 재조정**: 같은 정기 거래 + 같은 결제일시 회차는 최대 1개. 재조정·자동추가를 여러 번 실행해도 중복 거래를 만들지 않는다.
- **정기 거래 삭제**: 미래 회차 생성 중단. 이미 만들어진 거래는 보존(독립 기록으로 남음). 대기 중 회차는 제거.
- **재조정 시점**: 앱 진입 시 실행 — 밀린 회차를 그때 메운다. 앱을 열지 않으면 다음 진입까지 반영되지 않지만, 거래는 *결제일시 기준*으로 채워지므로 누락이 아니라 지연이다.
- **결제수단 잔액 미관리**: 카드/계좌는 "무엇으로 냈는지" 라벨일 뿐, 잔액·한도·이체를 추적하지 않는다.
- **결제수단 부착**: 거래·정기 거래에 선택적으로 붙는다(없어도 됨). `type`(card/account)은 생성 후 불변.
- **결제수단 아카이브**: 선택 목록에서 숨기되 관리 화면·기존 거래 표시에는 남는다. 되돌릴 수 있다.
- **결제수단 삭제(완전 삭제)**: 사용 거래가 있으면 먼저 확인. 진행하면 그 결제수단을 참조하던 거래·정기 거래의 결제수단만 비우고(set null) 거래는 보존.
- **단일 사용자 인증**: 회원가입 없음. 자격증명(이메일·비밀번호·PIN)은 운영자가 직접 주입한다. 비밀번호 재설정 흐름 없음(분실 시 시크릿 재주입). 기술 설계는 `CLAUDE.md` §7.
- **빠른 PIN 자격**: 풀 로그인한 브라우저만, 유효기간(기본 30일) 안에서 PIN 키패드를 제공받는다. 유효기간이 지나면 풀 로그인으로 되돌아간다.
- **PIN 무차별 방지**: PIN은 그 브라우저에 한해 검증되며, 연속 실패가 한도(기본 5회)를 넘으면 그 브라우저의 빠른 로그인을 해제한다.

## 9. 성공 지표 (How do we know it's working?)

- 거래 1건 입력 평균 ≤ 10초.
- 정기 거래로 인한 지출 누락 0 — 한 달 구독·공과금을 빠뜨리지 않는다.
- 월말에 요약 화면만 봐도 한 달 지출 패턴이 보인다.

## 10. 리스크 / 가정 (Risks & assumptions)

|---|---|---|---|
| 1 | 입력을 까먹는다 | 데이터 누락 → 요약 신뢰도 하락 | 홈 화면 단축 + 정기 거래 자동화 |
| 2 | 앱 미접속 기간 동안 자동추가가 지연 | 최신성 저하(데이터는 다음 진입 시 결제일시 기준으로 정확) | 앱 진입 재조정. 필요 시 P2 서버 cron 백스톱 |
| 3 | 정기 등록값 ≠ 실제 청구액 | 요약 부정확 | 알림 승인 모드로 확인 후 사후 수정 |
| 4 | OS 푸시가 없어 알림을 놓침 | 정기 확인 지연 | 윈도 D+5까지 노출 + 만료 처리 옵션 |
| 5 | PIN 무차별 / 디바이스 쿠키 탈취 | 무단 접근 | 디바이스 토큰 전제 + 실패 한도 잠금, HttpOnly·Secure 쿠키, PBKDF2 해시 |

## 11. 마일스톤

> 코드 phase는 `CLAUDE.md` §11. 여기는 *기능 단위* 마일스톤.

- **M1**: 거래 입력(지출명 · 발생일시 포함) + 목록 + 요약 동작, 본인 사용 시작.
- **M2**: 카테고리 편집 + PWA 완성.
- **M3**: 정기 거래(등록 · 재조정 · 인앱 알림 · 승인/해제 · 만료 처리).
- **M4**: 데이터 export(JSON 압축) — 백업 대용.

## 12. 결정된 기본값 (Resolved defaults)

> 임의 결정 가능한 항목을 합리적 기본값으로 확정. 변경 시 관련 섹션과 함께 갱신.

- **지출명**: 필수. 비어 있으면 거부(카테고리명 자동 채움 없음).
- **관리 진입점**: 카테고리·결제수단·정기 거래 관리는 **요약의 "관리"에서 시트**로 진입(4번째 탭 추가 안 함).
- **인앱 알림 위치**: 입력 화면 **상단 배너**.
- **'계속 보류'(keep) 정리**: 자동 정리 없음 — 승인/해제할 때까지 배너에 남는다.
- **정기 거래 일시정지/종료일**: P2(MVP 제외).
- **퀵 PIN**: 6자리 숫자, 디바이스 유효기간 30일.
- **PIN 실패 복구**: 5회 초과 시 풀 로그인으로만 복구(추가 쿨다운 없음).

비번/PIN 해시: **PBKDF2(WebCrypto)** 로 확정(`CLAUDE.md` §7.4 — argon2id는 의존성 부담으로 보류, 인터페이스 교체 가능).
