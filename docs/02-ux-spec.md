# UI / UX 기획 — 가계부 PWA

> 이 문서는 **어떻게 보이고 어떻게 동작하는지**를 정리한다.
> 무엇/왜는 `docs/01-service-spec.md`, 코드/스택은 `CLAUDE.md`.

## 1. 디자인 원칙 (Principles)

> 모든 화면 결정은 아래 두 대원칙을 통과해야 한다. 충돌 시 1번 — 폼팩터별 정체성이 더 우선.

### 1.1 대원칙

#### A. 웹뷰 — 한 화면에 최대한 많이 (정보 밀도 우선)
넓은 화면을 단순히 모바일 레이아웃을 가운데 띄워두는 데 쓰지 않는다. 같은 시간에 더 많은 맥락(여러 달, 카테고리 분포, 거래 목록, 입력 폼 등)을 동시에 보이게 해서 **분석/회고**에 강한 뷰를 만든다.

- 데스크탑/태블릿 폭에서는 **다중 컬럼**·**더 많은 행 노출**·**그래프와 표 동시 표시**를 기본으로 한다.
- 모바일 max-w-md 컨테이너를 데스크탑에서 그대로 쓰지 않는다 — breakpoint마다 별도 레이아웃을 설계한다.
- 호버, 키보드 단축키, 마우스 우클릭 같은 데스크탑 네이티브 인터랙션을 적극 활용한다.

#### B. 모바일 — 최소 정보·최소 동작 (입력 마찰 0에 가깝게)
가계부에서 지출 한 건을 적는 데 시간이나 탭 수가 늘어나면 **그 즉시 안 쓰게 된다**. 모바일은 *분석 도구*가 아니라 *입력 도구*다.

- 현재 액션에 **필요한 정보만** 표시한다. 메타 정보·통계·필터는 한 탭 뒤로 숨긴다.
- 가장 흔한 액션(거래 1건 입력)은 **앱 열고 N탭 이내** 완료를 목표로 한다 (N은 §4.1에서 측정·합의).
- 시스템 키보드·시스템 컨트롤을 기본값으로 — 커스텀 UI로 단계 늘리지 않는다.
- 확인 다이얼로그·다단계 마법사 등 "한 번 더 누르라"는 패턴은 데이터 손실 위험이 있을 때만 사용.

### 1.2 보조 원칙

> 두 대원칙을 뒷받침. 사용하면서 채워나가기.

- **숫자가 주인공** — 금액은 큰 글자, tabular-nums, 부호(+/-)와 색을 함께 사용.
- **색은 의미를 갖는다** — `primary`=수입/CTA, `destructive`=지출/위험. 그 외엔 의미 부여 금지.
- **입력은 실패해도 폼이 비워지지 않는다** — 어떤 실패에서도 사용자 입력 보존.

## 2. 정보 구조 (IA / Navigation)

```
[Bottom Nav]  ┌─ 입력  (default) ── 상단: 정기 도래 알림 배너(승인/해제)
              ├─ 내역
              └─ 요약 ── (icon) 관리: 카테고리 · 결제수단 · 정기 거래 · 데이터 내보내기
```

- **진입점**: 도메인 접속 → 인증 게이트 → 기본 랜딩 = **입력 화면**. 미인증이면 디바이스 기억 여부에 따라 **PIN 키패드(퀵 잠금해제)** 또는 **이메일+비번 로그인**(§7 `CLAUDE.md`).
- **탭 모델**: 하단 3탭 고정(§1.1.B). 관리성 화면(카테고리·결제수단·정기 거래)은 탭을 늘리지 않고 요약의 **관리** 진입점 뒤로 둔다.
- **탭 전환**: 상태 보존(입력 중인 폼은 탭 이동 시 유지).
- **모달/시트**: 거래 수정·삭제, 카테고리/결제수단 편집, 정기 거래 등록·수정은 sheet/dialog로(라우터 없이 상태 기반).
- **정기 알림**: 입력 화면 진입 시 재조정 → 윈도 내 대기 회차가 있으면 상단 배너로 노출, 승인/해제.

### 4.6 결제수단 관리 (PaymentMethodEditor)
- **목적**: 카드/계좌를 추가·정리. 잔액은 다루지 않음.
- **주요 콘텐츠**: 카드/계좌 그룹 목록 · 이름·종류 · 아카이브 토글 · 삭제.
- **인터랙션**:
    - 아카이브 = 선택 목록에서 숨김(여기엔 "아카이브됨"으로 남음). 되돌리기 가능.
    - 삭제 = 사용 거래 수 확인 다이얼로그 → 진행 시 거래의 결제수단만 비움(set null).
- **엣지 케이스**: 사용 중 삭제(확인 강하게), 아카이브된 항목만 남은 목록.

### 4.7 정기 거래 관리 (RecurringScreen)
- **목적**: 정기 거래 등록·수정·삭제.
- **주요 콘텐츠**: 정기 목록(다음 도래일 · 금액 · 모드) · 등록/수정 폼.
- **폼 필드**: 등록명 · 종류(지출/수입) · 금액 · 카테고리(선택) · 결제수단(선택) · 주기(연/월/주/일) · 결제일시 앵커(주기별: 월·일·요일·시각) · 모드(자동추가/알림승인) · (알림 모드면) 만료 처리(스킵/추가/계속 보류).
- **인터랙션**:
    - 주기 선택에 따라 앵커 입력 필드가 바뀜(연 = 월+일+시각 … 매일 = 시각).
    - 삭제 = 미래 회차 중단(생성된 거래는 보존) 안내.
- **엣지 케이스**: 말일(31일) 선택 시 짧은 달 보정 안내, 모드 전환 시 만료 처리 노출/숨김.

### 4.8 정기 알림 배너 (입력 화면 상단)
- **목적**: 도래 회차를 그 자리에서 승인/해제.
- **주요 콘텐츠**: 윈도(D-3~D+5) 내 대기 회차 카드(등록명 · 예정일 · 금액) · [승인] [해제].
- **상태**: 빈 윈도면 미표시 / 1건 / 여러 건(목록).
- **인터랙션**: 승인 → 거래 생성 + 토스트, 해제 → 사라짐. '계속 보류' 만료분도 여기 노출.
- **엣지 케이스**: 다수 누적(보류 쌓임), 승인 직후 내역 반영.

### 4.9 로그인 (LoginScreen)
- **목적**: 이메일+비밀번호로 인증.
- **주요 콘텐츠**: 이메일 · 비밀번호 · 로그인 버튼. (회원가입/비번찾기 없음 — 단일 사용자)
- **상태**: idle / submitting / error(자격증명 불일치).
- **인터랙션**: 성공 → 입력 화면. 이 브라우저를 기억(다음부터 PIN 키패드).
- **엣지 케이스**: 반복 실패(레이트 제한 안내), 네트워크 오류.

### 4.10 퀵 잠금해제 (QuickUnlockScreen)
- **목적**: 기억된 브라우저에서 PIN만으로 빠르게 진입.
- **주요 콘텐츠**: 숫자 키패드 · PIN 자릿수 점 표시 · **"일반 로그인으로"** 버튼.
- **상태**: idle / 검증 중 / 실패(남은 시도 표시) / 잠금(한도 초과 → 풀 로그인).
- **인터랙션**: 자릿수 채우면 자동 제출. 실패 시 흔들림 + 남은 횟수. 한도 초과 → 로그인 화면.
- **엣지 케이스**: 유효기간 만료(키패드 대신 로그인), 디바이스 쿠키 없음.

## 5. 컴포넌트 인벤토리 (Component inventory)

> 이미 들어온 shadcn 원시 + 필요한 합성 컴포넌트.

**shadcn 원시(설치 완료)**
- Button · Input · Label · Card · Separator · Badge · Sonner(Toaster)

**추가 설치 예정**
- <!-- Sheet / Dialog (수정·삭제·카테고리 편집) -->
- <!-- Tabs(상단 필터?) — 또는 Toggle Group -->
- <!-- Select(카테고리/kind?) -->
- <!-- Calendar / DatePicker (날짜 입력 고도화 시) -->
- <!-- Progress (카테고리 막대) -->

**합성 컴포넌트(직접 작성)**
- `AmountInput` — 큰 숫자, tabular-nums, 콤마 포맷
- `KindToggle` — expense/income 2-way 토글
- `CategoryChips` — 카테고리 선택 칩(활성만, kind와 무관하게 전체)
- `PaymentMethodChips` — 카드/계좌 선택 칩(아카이브 제외)
- `DateTimeField` — 발생일시(기본 now, 날짜+시각 수정)
- `MonthPicker` — `YYYY-MM` 선택
- `TransactionCard` — 내역 한 줄(정기 출처 배지 포함)
- `CategoryBar` — 카테고리별 막대
- `CyclePicker` — 주기 선택 + 주기별 결제일시 앵커 입력
- `RecurringForm` — 정기 거래 등록/수정 폼
- `OccurrenceAlert` — 정기 도래 알림 카드(승인/해제)
- `PinKeypad` — 숫자 키패드 + PIN 자릿수 점 표시

## 6. 상태 패턴 (States)

모든 데이터 화면은 다음 4상태를 반드시 정의:

| 상태 | 표시 | 조건 |
|---|---|---|
| **loading** | <!-- skeleton card? spinner? --> | 초기 fetch 중 |
| **empty** | <!-- 일러 + 짧은 안내 + CTA --> | 결과 0건 |
| **error** | <!-- 토스트 + inline retry --> | fetch 실패 |
| **idle/ok** | 정상 렌더 |  |

저장 액션은 추가로:
- **saving** — 버튼 비활성 + spinner
- **success** — toast 1초
- **failure** — toast(destructive) + 폼 상태 유지

## 7. 입력 / 폼 패턴 (Forms)

- **금액**: `inputMode="numeric"`, 입력값은 숫자만 허용, 표시는 콤마(`123,456`), 제출은 정수.
- **지출명**: 짧은 텍스트, 필수(비우면 거부 — 자동 채움 없음).
- **일시**: 기본 현재 시각(KST), `type=datetime-local`로 시작. 후속에 더 빠른 패턴 검토.
- **카테고리**: 칩 그리드. kind와 무관하므로 토글과 상관없이 전체 노출.
- **결제수단**: 칩(카드/계좌, 아카이브 제외). 선택 안 함 허용.
- **메모**: 선택. 너무 길면 줄임표.
- **저장 실패**: 폼 상태 보존, 어떤 필드가 문제인지 inline.

## 8. 접근성 (Accessibility)

- 터치 타깃 ≥ 44×44 pt.
- 색만으로 의미 전달 금지 — 지출/수입은 부호(`-`/`+`)와 색 둘 다.
- 폼은 `<Label htmlFor>`로 input과 연결.
- 다이얼로그/시트는 ESC + 외부 탭으로 닫힘, 포커스 트랩.
- `aria-current="page"` — 활성 탭 표시.
- 키보드 단축키: <!-- 데스크탑에서 1/2/3 탭 전환? Enter 저장? -->

## 9. 반응형 / 안전 영역 (Responsive)

> §1 대원칙대로 **모바일과 데스크탑은 별개의 레이아웃**으로 설계한다. 같은 화면을 폭만 늘리는 게 아니다.

- **모바일 (~md)**: 390px 기준, 콘텐츠 max-w-md 가운데 정렬. 한 번에 하나의 일에 집중.
- **태블릿/데스크탑 (md+)**: 다중 컬럼. 입력 폼·내역·요약을 동시에 보이는 *대시보드* 형태를 기본으로 한다. 호버·키보드 단축키 활성.
- **safe area**: `env(safe-area-inset-bottom)` — 하단 탭 + 메인 영역 보정.
- **iOS Safari**: `100dvh` 사용, viewport-fit=cover.
- **분기 기준**: Tailwind `md:` (≥768px)부터 데스크탑 레이아웃 진입.
